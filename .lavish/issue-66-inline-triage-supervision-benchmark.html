Decision and authority boundary

Recommendation: keep SQLite and model-authored semantic triage; make the active Shotcaller emit the ordered JSON sideband in its existing turn. A second classifier is allowed only for asynchronous orphan/backlog recovery.

The owner-response path starts one league request turn process and zero classifier processes. League does mechanical work only: exact prompt capture, candidate inventory, schema validation, deterministic IDs, candidate-version checks, claims, routing validation, and atomic commits.

No live claim. This branch did not install files, edit hooks, render/load a launch service, change model routing, import canonical state, start supervision, or run the installed #23 lifecycle. Source tests are not installed proof.

Owner-source P0 findings

Persistent supervision was off

No League/watch service owned a renewable event-driven lease. The benchmark process was isolated evidence, not supervision.

Live capture was broken

Genuine owner steers arrived, yet the active turn's final canonical boundary still reported zero untriaged prompts. Earlier read-only preflight reached state_root_unavailable.

The currently installed 0.2.28 command inventory does not expose the new service lifecycle. Therefore nothing in this artifact should be read as installed or active behavior.

Target source flow

The question this flow answers: where does semantic judgment happen, and which work can delay the owner?

Exact capture

UserPromptSubmit publishes exact event identity and bytes.

Persistent wake

One fenced service socket accepts user priority outside model turns.

Bounded intake

One turn process emits prompts plus a small same-owner candidate shortlist.

Inline semantics

The already-active Shotcaller authors ordered items and routing JSON.

Local commit

League validates, links, exact-deduplicates, and commits SQLite atomically.

Fallback: quarantined or ownerless backlog may be sent to an injected recovery adapter asynchronously after capture returns. This source slice selects no production recovery model.

SQLite performs exact source-event idempotency only. Paraphrase or follow-up matching remains an active-Shotcaller semantic decision. No embeddings or vector store were added.

Stop and post-creation reconciliation

Stop: omission only

Stop surfaces bounded unresolved summaries. It never merges, cancels, or relinks a request.

Shotcaller: explicit repair

request reconcile-duplicate may supersede B with canonical A under both expected versions.

The schema-19 transition preserves both source histories, creates no task/work/result, releases B's claim, prevents B dispatch, records one immutable event, and is exactly idempotent. It refuses self-links, chains/cycles, cross-owner/Squad links, stale or terminal state, and any B with external execution evidence.

Persistent service boundary

One service-manager-owned agent-watcher --shotcaller <callsign> service-run process owns a state-root lock, same-user Unix socket, and renewable monotonically fenced watcher registration. Hooks are short socket clients. User messages outrank Champion events. Startup replays pending delivery and schedules orphan/backlog recovery off-path; bounded stop releases only its exact registration and socket.

The repository carries an inert launchd template with placeholders. Rendering, installation, loading, live status, and rollback are separate owner-authorized gates.
