01 · authority

A lens, never a second store

The catalog recognizes projects and names suggested Squads. The Roster snapshot groups canonical facts inside one bounded read transaction. Neither surface can assign, route, rewrite history, copy instructions, or infer success.

Explicit wins

A user’s route is displayed separately. Suggestions never override or replace it.

Unavailable stays named

A retired Squad remains visible with a reason. Work is not silently rebound.

Evidence stays exact

Every claim links to table, key, version, and the latest event or transition when present.

03 · comparison

Three low-cost shapes

All three can be rendered from the same snapshot. The decision turns on project hierarchy, narrow-terminal behavior, and evidence drill-down—not visual novelty.

Recommended · A

Project Ledger

  • Single semantic reading order
  • Project context survives 80 columns
  • Natural selected-row evidence pane

Cost: cross-project status comparison needs filter or search.

Alternative · B

Status Columns

  • Fast blocked-versus-ready comparison
  • Familiar wide-screen scan
  • Project names repeat in every lane

Cost: horizontal movement and narrow terminals fight the hierarchy.

Fallback · C

Plain Report

  • Best for pipes and print
  • No focus model
  • Smallest renderer

Cost: weak frequent scanning and no persistent detail context.

06 · interaction contract

Navigation without command authority

The future process reads at startup and on explicit refresh. Focus is restored by exact entity ID after a schema-complete replacement snapshot.

Move and inspect

  • j/k or arrows move rows
  • h/l collapse or expand
  • Enter opens read-only detail
  • / filters; n/N finds
  • ? help; q exit

Refresh and fail honestly

  • r requests exactly one new snapshot
  • No automatic polling in the first slice
  • Malformed or partial responses never render
  • Old in-memory view is marked stale after failure
  • Runtime unavailable remains unknown, not failed

Accessible by construction

  • Status symbol plus full word
  • NO_COLOR and ASCII fallbacks
  • One top-to-bottom reading order
  • Reserved line announces refresh and focus changes
  • TERM=dumb emits the plain report

Truncate deliberately

  • Below 80 columns, hide aliases then repeated Squad then age
  • Never hide status, selected callsign, task ID, blocker marker, or bound
  • Wrap full values in details
  • No horizontal scrolling
  • No durable UI cache
No action keys: assign, route, send, merge, deploy, stop, teardown, and retry-work are categorically outside this design.

07 · implementation boundary

The smallest later slice

A separate issue may implement the selected layout only after acceptance. It consumes the stable snapshot; it does not extend canonical state.

Read-only renderer

One process, one stable snapshot facade, one vertical hierarchy.

  1. Read one local-only league.roster-snapshot.v1 value without logging or exporting private fields.
  2. Validate the response completely before replacing the view.
  3. Render Project Ledger navigation, details, help, and manual refresh.
  4. Cover empty, active, blocked, ready, stale, unavailable, large, and failure states with synthetic golden tests.
  5. Exclude adapters, root/repository display, polling, pagination, persistence, actions, and controller behavior.
